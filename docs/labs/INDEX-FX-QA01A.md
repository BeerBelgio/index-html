## Method and limitations
- Original compositor and manifests unchanged; no eval of HTML FX. SHA-256 of each original export; catalogue IDs; default and each min/max, choice, toggle and two colors tested one at a time. Three deterministic frames per case; independent history reset between cases. Asymmetric dry corner check for chart sources. Motion source follows fixed frame sequence. Favicon and real Linking Nodes generator alternatives (generator determinism not certified).
- Technical PASS verifies first frame, render/readback, frame count and representative history lifecycle. Output alpha and variance are observations, not artistic oracles. Default PNG thumbnail and raw RGBA hash in JSON, per-case state and statistics. No standalone parity claim, no per-uniform GPU introspection, no all-FX orientation/visual equivalence or independent two-instance/resize QA in this phase. Existing integration tests cover generic multipass and independent history.
- CPU measured render-call wall time excluding bitmap creation/readback; 3 warmup frames and 12 samples, not steady-state FPS. GPU query measures whole compositor when supported; discard disjoint and unresolved samples, no per-pass timing. Actual target capped at 2048 largest dimension; texture estimate is not total VRAM. No 4K native claim. 30/60 selects simulated timeline step only; no real-time benchmark. Native sustained performance, frame pacing, pass cost and serial effects remain QA-02/03.
- Report is local; JSON includes environment/metadata, case details and evidence; CSV is one row per selected module. Software Chromium pilot is infrastructure evidence only. UI smoke, native pilot and full 38-case matrix remain separate.
- Reproduce CI: from repo root start server on 8774 and run `node tests/run-browser-smoke.mjs http://127.0.0.1:8774/tests/fx-qa-pilot.html fx-qa-pilot-result.html chromium` using Node with native WebSocket and installed Chromium. No new dependencies. One targeted Actions run on the lab branch only.
