Quick start

1

Pick a layer

Open L1–L5. Only one Layer editor is open at a time.

2

Select it from the library, check its status, then LOAD / UPDATE / DOWNLOAD explicitly.

3

Open PARAMETERS, COLORS & BLEND and MIDI MAPPING in any combination.

Render live

5

Export offline

REC sets range, quality, ratio, FPS, output and audio. EXPORT runs the offline job.

Core The permanent strip: project, help, live output, REC and the five Layers. +
Layers Five independent visual slots, composed from L1 upward. Effects process only what sits below them. +

One editor, five layers

Open one Layer editor at a time. Layer visibility is independent from whether its editor is open.

Tool loading

Choosing a tool in the dropdown only selects it. Loading is explicit, and loading a tool restores its manifest defaults.

Generator vs effect

Generators draw their own canvas. Effects receive the composite of the Layers beneath them and process that result.

Remembered per layer

Only the open/closed state of PARAMETERS, COLORS & BLEND and MIDI MAPPING is remembered. Tool parameter values are not stored per tool.

Parameters Twelve numeric slots per Layer, mapped to each tool’s own manifest labels and ranges. +

Native Live parameters

The device exposes a stable Live parameter registry for automation and external modulation.

Reset & defaults

Use the single reset beside a parameter for that control only. DEFAULT restores the loaded tool’s manifest defaults.

Effective values

MIDI contributions are added to the base Live parameter value, then clamped and converted back through the tool’s native range.

Automation stays yours

The base Live parameter remains the automation/modulation target even while MIDI is contributing to the value sent to the renderer.

Colors & Blend Up to four tool-defined colors, independent opacity and per-Layer blend mode. +

Colors

Each active color can be edited with the picker or six-digit HEX input. Unused manifest slots stay clearly marked.

Opacity

Color opacity is a native host control and does not consume P01–P12. Missing host opacity keeps the standalone tool behaviour unchanged.

Blend

Effects

Effect Layers do not use generator blend in the same way: their shader processes the lower composite directly.

MIDI Mapping Map NOTE or CC directly onto P01–P12 with amount and envelope/smoothing controls. +

Source

Mappings start unassigned. Routing is user-managed through the native MIDI input/channel selectors.

NOTE

Velocity becomes the modulation peak. Attack rises to that peak, then release returns automatically to zero.

CC

The incoming 0–127 value becomes the target. Attack smooths upward movement; release smooths downward movement.

During offline export

INDEX records the final effective renderer controls it actually receives. Raw MIDI is not re-mapped later during offline replay.

Library CHECK INDEX compares your local HTML tools with the INDEX catalogue. Nothing updates by itself. +

Status

CHECK INDEX

Refreshes the remote catalogue and compares it with the flat local tools/ library. It does not download tools automatically.

Selected tool

Depending on state, the action becomes LOAD, UPDATE or DOWNLOAD. A dropdown selection alone never changes the running Layer.

UPDATE ALL

Queues only MISSING and OUTDATED catalogue tools. CURRENT entries are left untouched; local-only fixtures remain local.

Render RENDER is the live window. It is separate from REC and the offline export engine. +

Live output

RENDER launches the localhost compositor in an external Chromium app window. Live state reaches one compositor SSE connection, then the five tool iframes through postMessage.

Requirements

A ready local Node host, a supported installed Chromium browser and compatible Canvas/WebGL support are required.

RENDER ≠ REC

The live window does not need to be open for offline export. REC launches its own dedicated export renderer.

REC / Offline Export Capture the effective Live controls, then rebuild the visual offline frame by frame. +

1 · Acquire

Live runs once through FROM BAR → TO BAR while INDEX records the effective controls that reach the renderer.

2 · Replay

The export Chromium rebuilds the sequence at deterministic frame times. It may render slower than realtime without changing musical time.

3 · Encode

PNG frames are always produced. If MP4 or MOV is selected, the bundled encoder builds and verifies the video afterwards.

Current output options

Audio INPUT records the stereo signal entering INDEX in a second realtime pass. Final mux is a separate stage. +

Source

INDEX records its own stereo input. Put INDEX on Main after the effects you want captured, or route Main/Resampling into the INDEX track yourself.

Second pass

Visual/control acquisition happens first. With AUDIO INPUT selected, Live then runs the chosen musical range again for native disk audio capture.

Files

The native recorder creates audio-capture.wav; the finalizer trims and validates a separate audio.wav when the complete range passes.

Video audio

The current MP4/MOV encoder produces silent video. Automatic mux is not yet available.

Current limitations

    Under the hood Only if you care: how Max, Node and Chromium divide the work. +

    Max / Live

    Owns the device UI, Live parameter identities, MIDI mapping, transport acquisition and native stereo input recorder.

    Node

    Owns the localhost bridge, library/filesystem state, Chromium launch, frozen export jobs, PNG persistence and media encoding/finalization.

    Chromium

    Owns Canvas/WebGL drawing, five-Layer composition, effect processing and deterministic offline frame generation.

    No Jitter renderer

    INDEX HTML stays browser-native. The fundamental split is simple: Max decides what happens; the browser decides how to draw it.
